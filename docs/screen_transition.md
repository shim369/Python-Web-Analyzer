# 画面遷移・処理フロー図

メイン画面を中心に、Excelインポートから非同期スクレイピング、判定、および結果ダウンロードの処理フローです。

```mermaid
%%{init: {'flowchart': {'curve': 'linear'}}}%%
flowchart TD
    A[メイン画面: ダッシュボードGUI] --> B[サイドバーで「担当者名」を入力]
    B --> C[Excelファイルを選択 ➔ ExcelServiceでB列のドメインリストをパース]
    C --> D[現在の日付 M/D を取得し、ScrapingJobを生成 ※page_thresholdは既定値10で固定]
    D --> E[「調査を開始する」ボタン押下]
    E --> F[担当者名の入力チェック ➔ 未入力ならエラー表示、入力済みならバックグラウンドスレッドで処理開始]
    F --> G[【状態】 調査処理中画面を表示 ＆ 約1.5秒間隔でポーリング更新]

    %% --- 2. バックグラウンド処理フロー（ドメイン単位で逐次実行） ---
    G --> H[SiteScraperServiceで1ドメインずつ順に処理]
    H --> I[SslCheckerでSSL状態を判定 ＆ HTTPS専用サイトはhttps直接接続でフォールバック]
    I --> J[WebCrawlerでwww.の揺れ・プロトコル不一致を吸収しつつ内部リンクを巡回]
    J --> K[繰り返しパストラップ検知でカレンダーページ等の無限リンクをスキップ]
    K --> L[CMS判定 / ナビゲーション抽出 / 問い合わせフォーム項目抽出 / ログイン・添付検知]
    L --> M{総ページ数 == 0?}
    M -- Yes --> N[調査結果を『要確認』に設定（接続不可/ボット拒否）]
    M -- No --> O{総ページ数が1〜2?}
    O -- Yes --> P[調査結果を『要確認』に設定（ページ数極小）]
    O -- No --> Q{階層数が『要確認』?}
    Q -- Yes --> R[調査結果を『要確認』に設定（階層深すぎ、別ツールでの確認を促す）]
    Q -- No --> S[RenewalEvaluatorで判定（ページ数超過/3階層以上/ログイン/添付/Lightbox/多言語/スクロールアニメーション等を判定し◯または×を確定）]
    N --> T[結果をSiteAssessmentへスレッドセーフに書き込み]
    P --> T
    R --> T
    S --> T
    T --> U{未処理ドメインが残っている?}
    U -- Yes --> H
    U -- No --> V[全ドメインの解析が完了 ➔ ジョブステータスを「completed」に更新]
    V --> W[【画面】 調査完了画面に切り替え]

    %% --- 3. ダウンロードフロー ---
    W --> X[「調査結果Excelをダウンロード」ボタン押下]
    X --> Y[ExcelServiceでA列に日付、B〜O列の結果をマージしたExcelを生成]
    Y --> Z[ブラウザ経由でローカルにダウンロード実行]

    %% --- 4. 異常系フロー ---
    H -.->|1ドメイン内で例外| AA[ログ出力のみ行い、そのドメインは初期値のまま次のドメインへ継続]
    G -.->|ワーカースレッド全体で予期しない例外| AB[ジョブステータスを「failed」に更新 ➔ 画面にエラーメッセージを表示]
```

## 補足・旧仕様からの変更点

* サイドバーに「カスタム閾値」を入力させるUI要素は**削除**されている。判定に使われる `page_threshold` は `ScrapingJob` の既定値（`10`）で固定運用される。
* 旧仕様にあった「閾値1〜3による◎/◯/△/×の4段階判定」は廃止され、現在は **◯/×の2値＋要確認** の運用になっている。
* 「要確認」に倒れる条件が3パターンに増えている（総ページ数0／総ページ数1〜2／階層数計測不能）。旧フローには階層数計測不能のケースが含まれていなかった。
* バックグラウンド処理は「ドメイン単位の逐次処理」であり、1ドメインの処理失敗（例外）はログに記録された上でそのドメインだけ初期値のまま次へ進む。ジョブ全体が失敗扱いになるのは、ループ全体を囲う外側の`try`で捕捉されなかった場合のみ。
